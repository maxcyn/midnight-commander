SecondShift

A manifest-driven on-call agent that correlates live Sentry telemetry and independent dependency probes with unified incident memory, enforces a two-layer deterministic policy gate, and phones the responder via Photon + ElevenLabs—turning every approved fix or refusal into verified operational memory.

01 // declarative contract service-manifest.json Plug-and-play definition of dependencies, read-only probes, causes, and idempotent actions.
02 // single investigator CREAO + 6 HTTP Tools Pulls Sentry spans/logs, live probes, config, and past_decisions to submit one grounded proposal.
03 // voice & auto-runbook Photon SIP + ElevenLabs Auto-provisioned voice tools for approval/refusal, or zero-touch execution for authorised runbooks.
04 // unified learning loop DB + incidents.md + Runbooks Auto-snapshots decline evidence, watches `/config` for manual fixes, verifies recovery, and syncs `incidents.md`.

02 // stages 01–02 (manifest.ts + investigation.ts)

Manifest-driven investigation & masked fault disambiguation

single creao agent · 6 read-only backend endpoints
plug-and-play investigator tools bearer tool_token

Evidence collected per incident run

  • GET /tools/service_manifest: Loads request path (validation → recommendations → payment → confirmation), probe paths, and allowlisted actions.
  • GET /tools/sentry_evidence & feature_config: Fetches scoped errors, logs, spans, and active flags—persisting each with a verifiable source_id.
  • GET /tools/probe?dependency=…: Runs live read-only probes on recommendations and payments to expose silent downstream degradation.
  • GET /tools/past_decisions: Returns prior approved/declined decisions, raw evidence_when_declined snapshots, incidents.md, and runbooks.
shared-pool masking // why both probes are mandatory identical sentry error ≠ identical root cause

Disambiguating the two checkout failure modes

Scenario Sentry & Rec. Probe Payment Probe Supported Cause Allowed Action
Rec. Outage recommendations timeout (>800ms) 40ms healthy recommendations_timeout disable_recommendations
Pool Degradation recommendations timeout (pool full) 1800ms (>1000ms) payment_provider_degradation switch_payment_provider
Payment Down recommendations ok (~40ms) unhealthy (502) payment_failure escalate only
agent-prompt.md invariant // independent root cause rule missing_information vs non_blocking_unknowns

If checkout fails at recommendations, payment code never runs—so absent payment errors prove nothing. When payment_provider_degradation saturates the shared pool, the agent marks only the root cause supported and treats the recommendation timeout as its symptom.

Deduplication & idempotency: Retried Sentry deliveries are ignored via webhook_events; CREAO run keys include incident_id + opened_at. 4-step onboarding via service-manifest.json

Mitigations set explicit state (expectedPreviousValue) rather than toggles. Recovery is never declared on silence:

Successful synthetic checkouts Correlated by incident run_id after execution timestamp.
≥ 30s

06 // unified incident memory (decision_feedback + incidents.md + runbooks) automatic closed-loop sync

How both approvals and refusals become operational memory

  • Decline snapshot (evidenceSnapshot): Declining a proposal—even without stating a reason—captures raw probe latencies (e.g. payments:1802ms), config, and failing stage into decision_feedback.
  • Automatic manual-fix detection (watchForEngineerFix): After a decline, the backend polls /config every 5s. When the SWE switches paymentProvider → backup (or disables recs), it automatically records manual_resolution_recorded and runs full Stage 6 verification.
  • Live Markdown sync (syncIncidentsMarkdown): Every decision and verified resolution automatically re-renders backend/incidents.md and generates a manifest-defined retrospective (separating mitigation from root-cause repair).
  • Evaluated runbooks (createLearnedRunbook): Verified human disable_recommendations fixes draft a versioned runbook tested against 13 deterministic cases (8 fixed + 5 held-out refusal/counterexample cases: draft → evaluated → authorised → suspended).
Safety invariant: Past lessons in /tools/past_decisions guide CREAO's next proposal but never expand the allowlist or bypass fresh probe gates. 13/13 fixed & held-out eval cases required

Three closed-loop scenarios

scenario 01 refusal + watch
Masked Pool Fault

Recs time out (800ms) while payment probe is 1800ms. If disable_recommendations is proposed, Gate 2 blocks or SWE declines. Backend snapshots probes, detects SWE's switch to backup, verifies recovery, and syncs incidents.md.

stored → decision_feedback
scenario 02 learned fix
Guided Recurrence

Masked degradation recurs. CREAO reads /tools/past_decisions, matches fresh 1800ms payment probe against evidence_when_declined, cites consulted_decisions, and proposes switch_payment_provider. One phone approval resolves.

0 wrong actions run
scenario 03 authorised
Evaluated Runbook

Genuine rec outage approved & verified → drafts checkout-disable-recommendations v1 (passes 13/13 fixed & held-out cases). Primary responder authorises it; next genuine outage executes automatically if fresh payment probe is healthy.
