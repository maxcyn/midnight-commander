02 // onboarding & investigation

Plug-and-play for any service in 4 steps

manifest-driven · no custom agent code required
how any team adopts secondshift 4-step onboarding

From zero to live responder

  • Write service-manifest.json: Declare your service's dependencies, health probes, and safe fix endpoints.
  • Attach to CREAO: Clone the investigator agent and upload your manifest file.
  • Add API keys: Point Sentry, CREAO, Photon, and your app URLs in .env.
  • Provision voice in 1 command: Run npm run configure:voice to auto-configure the phone agent.
why manifest probes beat logs alone surface symptom ≠ root cause

How live probes diagnose any architecture

Outage Type What Logs Show What Probes Show Action Taken
Feature Down Feature A times out Core APIs fast Disable non-critical feature
Shared Bottleneck Feature A times out Provider slow Fail over to backup provider
Core Outage Hard 5xx errors Core failing Escalate to engineer
why independent probes matter shared pools & queues

When services share connection pools or rate limits, a slow upstream provider makes unrelated features time out first. Probing each dependency directly stops the AI from fixing the wrong thing.

Takeaway: Any service with health endpoints and safe mitigation hooks can plug into SecondShift in minutes. zero hardcoded service logic

06 // how the system learns database + incidents.md + runbooks

Turning human decisions into memory

  • Snapshot on "No": Saves live probe readings whenever an engineer declines a proposal.
  • Watch manual fixes: Polls your service config to detect what the engineer changed instead.
  • Update logbook: Writes root cause, fix, and follow-up work to incidents.md.
  • Draft runbooks: Turns proven fixes into reusable runbooks tested against safety cases.
Safety rule: Past memory guides the next diagnosis, but never skips live safety checks. verified before closing
